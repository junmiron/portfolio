A local-first AI business analyst that interviews you about your project and writes a traceable functional spec, process diagram and PDF.

BA-GPT (v1.3.0) is a local-first, multi-agent business analyst that runs a budgeted, deterministic requirements interview with a human and produces a traceable Functional Specification Document. It is part of a Master's thesis (TFM) on multi-agent requirements elicitation. Core claim for analysts: the interview can run itself, and every deliverable traces back to a logged Q&A.

TL;DR

  • What: 11-agent AutoGen team (selector group chat) that interviews stakeholders and writes a 9-section functional spec.
  • Output: FSD in PDF, HTML and Markdown; Mermaid process diagrams; full Q&A audit trail.
  • Budget: Runs are capped by MAX_MESSAGES (default 300); only terminate_agent can end a run.
  • Runs on: Your machine, your LLM key. OpenAI, Azure, Groq, Hugging Face, GitHub, Ollama, LM Studio or a local server.
  • Status: v1.3.0 technical preview. MIT licensed. Beta.

What is BA-GPT?

BA-GPT is a local-first AI business analyst. It runs a budgeted, deterministic requirements interview with a human and drafts the functional spec, process diagrams and deliverables as reviewable artifacts. The interview is interactive by design: a human answers every question unless human simulation is enabled. The React web UI is the operator front-end; the Chainlit view is a debug surface, not a product.

How does the 11-agent pipeline work?

Eleven agents sit in one AutoGen 0.7.5 SelectorGroupChat. The planning agent decomposes the task and hands off with [ASSIGNMENT] markers; the interviewer asks one question per turn and every Q&A pair is saved to interview.jsonl. A summarizer requires the exact phrase APPROVE SUMMARY. The writer, glossary and use-case agents draft the spec; a checker bounces missing sections back up to three rounds, then a deterministic fallback fills the gaps. A diagram creator and a Mermaid reviewer produce the process diagram. Only terminate_agent can end a run, and only after the deliverables are written.

What do you get at the end of a run?

A session folder with the 9-section FSD (scope, FRs, NFRs, roles, assumptions, use cases, glossary) in Markdown, a Typst-typeset PDF with cover page and linked contents, a self-contained HTML file with the diagram inlined as vector SVG, the Mermaid source plus rendered PNG and SVG, and a timestamped Q&A audit trail. Tall diagrams are split into page-sized bands so nothing is clipped.

How do you run it?

Python 3.11 or 3.13, Node with mermaid-cli for diagrams, and an LLM of your choice. You bring your own API key, configurable per model lane from the in-app settings page. There is no hosted demo.

What does the test suite cover?

An offline pytest suite runs the whole 11-agent pipeline end to end with a scripted model client: no API key, no network. It covers selector routing, the termination guard, config hygiene, the FastAPI contract, transcript ingestion, spec continuation and Typst rendering.

Problem

Requirements work is slow: analysts interview stakeholders, then hand-write the spec, diagrams and deliverables. BA-GPT (v1.3.0 technical preview) runs a budgeted, deterministic interview with an 11-agent AutoGen team and drafts all of it as reviewable artifacts — FSD in PDF, HTML and Markdown, Mermaid process diagrams, and a full Q&A audit trail. It runs on your own machine with your own LLM key; there is no hosted demo.
