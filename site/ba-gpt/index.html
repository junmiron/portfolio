BA-GPT is an AI business analyst that interviews you about your project, then writes the functional spec for you: a PDF, a process diagram, and a full audit trail linking every requirement back to a question you answered.

Built as my Master's thesis in Artificial Intelligence on multi-agent requirements elicitation, designed and built by me. The app, files, indexes and rendering run locally. Remote model profiles send interview content to their provider; fully offline use requires a local model. Web RAG only fetches URLs listed in SITES (lib/rag_config.yaml).

TL;DR

  • What: A 10-agent team that interviews stakeholders and drafts a traceable functional spec.
  • You get: The spec in HTML (the recommended way to read it), PDF (for signed or printed copies) and Markdown (the best base for AI coding agents), a Mermaid process diagram, and a timestamped Q&A trail.
  • Why it's trustworthy: Every section traces to a logged answer. If a section is missing, a deterministic fallback fills it rather than letting the model invent one.
  • Runs on: The app runs on your machine. Local LLMs keep model calls local; cloud LLMs (OpenAI, Azure, Groq and more) receive interview content.
  • Stack: Python, AutoGen (SelectorGroupChat), FastAPI, React, TypeScript, Vite, ChromaDB/RAG, MCP, Mermaid, Pandoc + Typst.
  • Status: Technical preview (v1.3.0), MIT licensed.

Problem

Requirements work is the slow part of delivery. I wanted to find out whether an agent team could own the interview and draft the spec, with every claim traceable to a logged answer.

How it works

How does the 10-agent pipeline work?

Ten agents sit in one AutoGen 0.7.5 SelectorGroupChat. The planning agent decomposes the task and hands off with [ASSIGNMENT] markers; the interviewer asks one question per turn and every Q&A pair is saved to interview.jsonl. A summarizer requires the exact phrase APPROVE SUMMARY. The writer, glossary and use-case agents draft the spec; a checker bounces missing sections back up to three rounds, then a deterministic fallback fills the gaps. A diagram creator and a Mermaid reviewer produce the process diagram. Only terminate_agent can end a run, and only after the deliverables are written.

How is the interview budgeted?

Runs are capped by MAX_MESSAGES (default 300) and can only be ended by terminate_agent. The interviewer asks exactly one question per turn, and while the team waits for an answer, only the user may speak. Hand-offs are driven by explicit markers, not free conversation, so a run cannot drift or loop.

What do you get at the end of a run?

A session folder with the 9-section FSD in Markdown (Title Page, Introduction, Scope, Functional Requirements, Non-Functional Requirements, User Roles & Personas, Assumptions & Constraints, Use Cases, Glossary), plus open items, dependencies and risks; a Typst-typeset PDF with cover page and linked contents; self-contained HTML with the diagram inlined as vector SVG; the Mermaid source plus rendered PNG and SVG; and a timestamped Q&A audit trail. Tall diagrams are split into page-sized bands so nothing is clipped.

How do you run it?

Python 3.11 or 3.13, Node with mermaid-cli for diagrams, and an LLM of your choice — local (Ollama, LM Studio) or cloud (OpenAI, Azure, Groq). Cloud providers need their API key, configurable per model lane from the in-app settings page. There is no hosted live run, but a recorded replay of a full session plays in the browser with no install and no key.

What does the test suite cover?

An offline pytest suite runs the whole 10-agent pipeline end to end with a scripted model client: no API key, no network. It covers selector routing, the termination guard, config hygiene, the FastAPI contract, transcript ingestion, spec continuation and Typst rendering.

Terms

  • AutoGen — Microsoft's open-source framework for building conversations between several AI agents.
  • SelectorGroupChat — AutoGen's mode where all agents share one conversation and a selector picks which one speaks each turn.
  • MCP (Model Context Protocol) — An open standard for plugging external tools into an AI app. BA-GPT runs two MCP servers: one renders the process diagram, the other exports the documents.

Limitations

  • The interview is interactive: a human must answer every question unless human simulation is enabled.
  • The interviewer records answers and flags unconfirmed values as open items, but does not yet challenge a requested feature or contradictions between answers (see Next steps: post-spec review).
  • The summarizer only accepts the exact phrase APPROVE SUMMARY.
  • The config endpoint is unauthenticated and intended for local, single-user use.
  • The Chainlit view is a debug surface, not a finished product; the React UI is the front-end.

Next steps

Post-spec review steps (planned, not implemented): first, process review and improvement—map the current process and ask which decision or outcome to improve; then research and recommendations; then benchmark similar products to suggest questions and candidate targets for the owner to confirm. Benchmarking needs web access and will be opt-in, off by default. Docker/Compose packaging and /api/config authentication before non-local deployment are also planned.
